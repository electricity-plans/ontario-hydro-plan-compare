# Launch plan for the public beta

Start small and deliberate: a beta for a few dozen people first, not a big announcement.

## Before launch

- [ ] NVDA run-through done (`docs/verification-v2.0.md`, section 6).
- [ ] Five moderated usability sessions done (`docs/usability-test-plan.md`), and anything blocking fixed.
- [ ] Fresh public repository created from the current files only, with your private GitHub email.
- [ ] `docs/maintainers/repo-setup.md` checklist done; release `v2.0.0-beta.1` published (`releases.md`).

## Week 1

- Post the pinned "Looking for testers" discussion, and the invitation in one or two communities (with their
  moderators' permission where the rules ask for it).
- Answer questions on the day you post; it matters more than the post itself.

## Weeks 2 and 3

- Fix anything that stops people reaching a result, first.
- Add made-up test files for any utility format that turns up.
- Ask for one or two Firefox, Safari or Mac users if none have come forward.

## Week 4

- Release the fixes (`v2.0.0-beta.2`), with notes.
- Post a short summary in Discussions: what was learned, what changed, what's next.
- Decide whether to invite more people.

## What to track (no household data needed)

- Can people reach a result without help?
- Can they say what the saving is compared with?
- Can they say what they'd do first?
- Which utilities' downloads fail, and which browsers have problems?
- Which questions come up more than once? (Usually a sign the app or its help needs a change.)

A utility counts as checked only for the **export profile** that was checked against a bill (its web address,
reading length and units), not every file the utility could produce. Keep that separate from how accurate the
forecast turns out to be.
